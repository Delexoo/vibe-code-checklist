Open your app in Claude, Claude Code, Cursor, or any other coding agent. Copy the prompt below. Paste it into the chat that can read that project.

The prompt

Audit the project that is open right now against the Vibe Code Checklist.

You can be any coding agent. Use ordinary file reads and, if you have them, a web fetch. Do not install packages, plugins, or skills. Do not change application code.

First read this project and say what the app is for: the end goal, who it is for, and which features it actually has. Then judge only the checks that fit that app. A check the product does not need is not a failure.

Before you judge anything, read the procedure and the checklist from the raw files, not the GitHub web page:
https://raw.githubusercontent.com/Delexoo/vibe-code-checklist/main/PROMPT.md
https://raw.githubusercontent.com/Delexoo/vibe-code-checklist/main/checklist.json

If a raw address fails, try the same file name on https://delexoo.github.io/vibe-code-checklist/

Follow PROMPT.md exactly. Inspect this project, not the checklist repository. If you cannot read both files, stop and name the address that failed. Do not invent checks.

Write one self-contained HTML file named vibe-audit.html at the root of this project. If you cannot write a file, put that same HTML in your reply and say to save it as vibe-audit.html.

After the file exists, open it in the default browser if this machine has a desktop. If you cannot, say the full path and that the file is ready. Then reply with what the app is, the overall result, and the required items still open.

What the agent will do

The box above is the whole instruction. It points at the procedure file. These are the steps that file makes the agent follow, in order.

  1. Stay in the project that is open

    It audits your app, not this checklist. If the open folder is the checklist itself, it stops and tells you to open your own app.

  2. Read files, and leave the app alone

    It may read files and fetch a URL. It does not install packages, plugins, or skills. It does not change application code, and it does not depend on an editor-only command.

  3. Load the real checklist

    Before it judges anything, it reads the procedure and the checklist from the raw files, not the GitHub web page. If a raw address fails, it tries the same file name on this site. If it still cannot read both files, it stops and names the address that failed. It does not invent checks.

  4. Say what the app is before it scores

    From the README, the name, the screens, and the routes, it writes four things: the goal, who it is for, which features the product actually has, and which checks do not fit. A check the product does not need is not a failure. Unfinished work the app does need still fails.

  5. Judge every item once

    Each check gets one status. Done means it saw the requirement in a file. Missing means this app needs it and it is absent, a placeholder, or only a default. Does not apply means the product has no such feature. A recommended miss is a warning. A required miss is a fix before you ship. It cites a path. It never pastes a secret, and it never invents a file.

  6. Score only the checks that fit

    The score is the passes, divided by the checks that apply. Ready to ship means every one of those passes. Required checks are in place means only warnings remain. Not ready to ship means a required item failed.

  7. Write one report, and nothing else

    It creates or overwrites vibe-audit.html at the project root. The file stands alone: no scripts, fonts, or images from elsewhere. It lists every item under Missing, Warnings, Done, or Does not apply, plus what the app is, the score, and how to fix the required gaps. If it cannot write a file, it puts that same HTML in the chat.

  8. Open the report, then stop

    If the machine has a desktop, it opens vibe-audit.html. Then it replies with what the app is, the overall result, and the required items still open. It does not start fixing the app.
